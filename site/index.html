“Tests pass” doesn’t mean the app works

A mobile change only proves itself on a phone, and most pull requests never get that far.

  • Reviewers can't see the screen.A diff doesn't show whether the button still works, or whether a sheet now covers it.
  • Coding agents say “done” without opening the app.They change screens they have never seen, and unit tests can't tell.
  • UI tests cry wolf.When an emulator hangs, most tools report a failed test, and people learn to ignore red builds.

yepitran opens the app on real simulators and emulators, does what a person would do, and posts the proof where the review happens.

Made for people who ship mobile apps

Mobile developers

Check a fix on iOS and Android with one command before you ask for review. No test code goes into your app.

Reviewers and teams

Watch the change work in a video on the pull request, instead of checking out the branch and booting a simulator yourself.

Coding agents

Claude Code, Codex and similar agents write the scenario, run it, and read a verdict they can act on: an exit code and verdict.json.

Works with any iOS Simulator build (.app) and any Android .apk. Point it at a Flutter project and it builds both for you. Runs on macOS, on Linux for Android, and in GitHub Actions.

How it works

Four steps, the same every time, so a result means the same thing on your laptop and in CI.

  1. 1
    tap "Add task"type "Milk" into "Title"assert visible "Milk"

    You write the steps

    A short scenario in plain words: what a person taps, types and expects to see. Your agent can write it for you.

  2. 2

    It boots clean devices

    Its own iPhone simulator and Android emulator, freshly booted, with your app newly installed. It never touches another session's device.

  3. 3
    Recording

    It follows the script and records

    Every tap, every typed word read back, every check. The whole run is on video, with screenshots where you asked.

  4. 4
    PASS
    video.mp4  report.html  verdict.json

    You get one verdict

    PASS, APP FAIL or INFRA FAIL, with a report folder. If the device broke, it retries on a fresh one before it blames your app.

A flaky emulator is never your app's fault

Every attempt starts on a cleanly booted device. A failure counts against your app only when it happens again on a fresh one. Pick what goes wrong and see what yepitran decides.

Write the test the way you'd say it

One step per line, matched against what a person sees on the screen. Nothing to add to your app, and no selectors to keep up to date.

  • Taps land where a finger would.yepitran taps the part of a button that nothing else covers, so sheets and overlays can't steal the tap.
  • Typing is read back.After every entry it checks the field, so autocorrect or a slow keyboard can't quietly change your text.

Proof on every pull request

The GitHub Action runs your scenario on GitHub's own runners, iOS on macOS and Android on Linux. It uploads the video and screenshots and can post the verdict on the pull request.

The check fails only when the verdict isn't PASS. GitHub's runners are free for public repositories.

# .github/workflows/proof.yml
- uses: codenameakshay/yepitran@v0
  with:
    platform: ios
    app: build/ios/iphonesimulator/Runner.app
    scenario: .yepitran/smoke.proof
    comment: true
